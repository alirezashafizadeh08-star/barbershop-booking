# سامانه نوبت‌دهی آنلاین آرایشگاه (Barbershop Booking System)

این پروژه یک وب‌اپلیکیشن تمام‌عیار و سبک برای رزرو آنلاین نوبت آرایشگاه **تک‌آرایشگر** است. مشتریان می‌توانند بدون نیاز به ثبت‌نام یا ایجاد حساب کاربری، خدمات را مشاهده کرده و فقط با ثبت نام و شماره تماس نوبت خود را رزرو کنند. هزینه خدمات به صورت **حضوری در محل آرایشگاه** دریافت می‌شود. مدیر آرایشگاه نیز از طریق پنل مدیریت امن به اطلاعات نوبت‌ها، آمار روزانه و امکان لغو نوبت دسترسی دارد.

## معماری سیستم

پروژه به صورت مونو‌ریپو (Monorepo) با ساختار استاندارد npm Workspaces پیاده‌سازی شده و از دو بخش اصلی تشکیل شده است:

```
barbershop-booking/
├── client/              # کلاینت فرانت‌اند (React SPA + Tailwind v4 + Vite)
├── server/              # سرور بک‌اند (Express 5 + Prisma ORM + TypeScript)
├── scripts/             # اسکریپت اجرای هم‌زمان توسعه (dev.mjs)
├── docs/                # مستندات تکمیلی و سند PRD
├── start-site.bat       # راه‌انداز یک‌کلیکی ویندوز (اجرای مستقل کلاینت و سرور)
├── stop-site.bat        # توقف ایمن پردازش‌های متعلق به همین پروژه در ویندوز
├── package.json         # پیکربندی ریشه و ورک‌اسپیس‌ها
└── AGENTS.md            # راهنمای فنی و قوانین تجاری پروژه
```

1. **Frontend (Client):**
   - معماری تک‌صفحه‌ای (Single Page Application) در `client/src/App.tsx`.
   - استفاده از پروکسی داخلی Vite در محیط توسعه برای هدایت درخواست‌های `/api` به سرور محلی (پورت ۳۰۰۰).
   - اعتبارسنجی کامل فرم‌ها در سمت کلاینت با رعایت منطقه زمانی `Asia/Tehran` و هماهنگی مسیرهای عمومی (`/`) و مدیریت (`/admin`).

2. **Backend (Server):**
   - مبتنی بر Node.js و Express 5 با تایپ‌های کامل TypeScript.
   - لایه‌بندی شفاف: روت‌ها (`src/routes`)، سرویس‌ها (`src/services`)، ابزارهای کمکی و اعتبارسنجی (`src/utils`) و میدل‌ورها.
   - اعتبارسنجی مستقل سمت سرور با کتابخانه Zod و توابع اعتبارسنجی تقویمی بر مبنای `Asia/Tehran`.

3. **Database (PostgreSQL):**
   - میزبانی‌شده روی Supabase PostgreSQL و مدیریت‌شده از طریق Prisma ORM.
   - تضمین عدم تداخل نوبت‌های فعال (FR-9) در سطح پایگاه داده با استفاده از افزونه `btree_gist` و قید انحصار (`EXCLUSION CONSTRAINT`) روی بازه زمانی `tstzrange`.

## تنظیم متغیرهای محیطی

تنظیمات محرمانه و متغیرهای محیطی در پوشه `server/` نگهداری می‌شوند. یک فایل الگو به نام `server/.env.example` در پروژه قرار دارد:

۱. یک کپی از فایل نمونه در پوشه `server` با نام `.env` ایجاد کنید:

```bash
cp server/.env.example server/.env
```
*(در سیستم‌عامل ویندوز می‌توانید فایل را به صورت دستی کپی کرده یا از دستور `copy server\.env.example server\.env` استفاده کنید).*

۲. مقادیر زیر را در فایل `server/.env` تنظیم نمایید:

```env
# محیط اجرا
NODE_ENV=development

# پورت سرور اکسپرس (پیش‌فرض: 3000)
PORT=3000

# رشته اتصال به پایگاه داده PostgreSQL (Supabase Session Pooler پورت 5432)
DATABASE_URL=postgresql://postgres.[PROJECT_REF]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:5432/postgres

# مشخصات اولیه مدیر برای اسکریپت seed
ADMIN_USERNAME=admin
ADMIN_PASSWORD=replace-with-strong-password

# کلید امنیتی امضای نشست‌های مدیریت (حداقل ۳۲ کاراکتر / ۲۵۶ بیت)
ADMIN_SESSION_SECRET=replace-with-at-least-32-chars-cryptographically-random-secret
```

> **نکته امنیتی مهم:** هرگز فایل `server/.env` یا رمزها و کلیدهای اصلی را در گیت Commit نکنید.

## مایگریشن و داده‌های اولیه (Migration & Seed)

پس از تنظیم صحیح `DATABASE_URL` در `server/.env`، دستورات پایگاه داده را اجرا کنید:

### ۱. تولید کلاینت Prisma
```bash
npm run db:generate --workspace server
```

### ۲. اعمال مایگریشن‌ها بر روی پایگاه داده
```bash
npm run db:migrate:deploy --workspace server
```
این دستور ساختار جداول و قید انحصار تداخل نوبت‌ها (`appointments_no_overlap_active`) را در PostgreSQL اعمال می‌کند.

### ۳. ایجاد داده‌های اولیه (Seed)
```bash
npm run db:seed --workspace server
```
این اسکریپت موارد زیر را در دیتابیس ثبت می‌کند:
- آرایشگاه و شعبه پیش‌فرض (`Asia/Tehran`)
- آرایشگر فعال
- خدمات چهارگانه مصوب با قیمت و مدت‌زمان
- حساب کاربری اولیه مدیر با نام کاربری و رمز عبور تعیین‌شده در `server/.env`

## اجرای پروژه در محیط توسعه

پروژه دارای دو سرویس مجزا برای فرانت‌اند و بک‌اند است و به سه روش زیر می‌توان آن را اجرا کرد:

### روش اول: اجرای یک‌کلیکی در ویندوز (مستقل از ترمینال و Antigravity)
- برای راه‌اندازی: روی فایل **`start-site.bat`** در ریشه پروژه دابل‌کلیک کنید. این فایل هر دو سرویس Backend (`3000`) و Frontend (`5173`) را در دو پنجره مستقل ویندوز اجرا کرده و صفحه مشتری را در مرورگر باز می‌کند (بستن یک پنجره باعث توقف سرویس دیگر نمی‌شود).
- برای توقف ایمن: روی فایل **`stop-site.bat`** دابل‌کلیک کنید تا فقط پردازش‌های متعلق به همین پروژه متوقف شوند.
- آدرس‌های محلی:
  - صفحه مشتری: `http://127.0.0.1:5173`
  - پنل مدیریت: `http://127.0.0.1:5173/admin`
  - سلامت سرور: `http://localhost:3000/api/health`

### روش دوم: اجرای هم‌زمان با یک دستور واحد در ترمینال
در ریشه پروژه دستور زیر را اجرا کنید (اسکریپت `scripts/dev.mjs` هر دو سرویس را هم‌زمان بالا می‌آورد):
```bash
npm run dev
```
*(در PowerShell ویندوز، در صورت فعال بودن محدودیت `ExecutionPolicy` از `npm.cmd run dev` استفاده کنید).*

### روش سوم: اجرای هم‌زمان در دو ترمینال جداگانه

**ترمینال ۱ (بک‌اند):**
```bash
npm run dev:server
```
سرور اکسپرس روی آدرس `http://localhost:3000` اجرا شده و فایل‌ها را به صورت خودکار پایش می‌کند (`--watch`).

**ترمینال ۲ (فرانت‌اند):**
```bash
npm run dev:client
```
کلاینت Vite روی آدرس **`http://127.0.0.1:5173/`** در دسترس خواهد بود و درخواست‌های `/api` را مستقیماً به بک‌اند پروکسی می‌کند.

## فهرست APIهای پیاده‌سازی‌شده

تمام اندپوینت‌ها تحت پیشوند `/api` در سرور قرار دارند:

### اندپوینت‌های عمومی (Public)

| متد | مسیر | شرح |
|---|---|---|
| `GET` | `/api/health` | بررسی سلامت و پاسخگویی سرور |
| `GET` | `/api/services` | دریافت فهرست خدمات فعال آرایشگاه همراه با قیمت و مدت‌زمان |
| `POST` | `/api/appointments` | ثبت نوبت آنلاین با نام و شماره تماس مشتری (همراه با صدور کد رهگیری یکتا) |

### اندپوینت‌های مدیریت (Admin)
*این اندپوینت‌ها (به‌جز login) نیازمند هدر `Authorization: Bearer <token>` هستند.*

| متد | مسیر | شرح |
|---|---|---|
| `POST` | `/api/admin/login` | احراز هویت مدیر با نام کاربری و رمز عبور و دریافت توکن معتبر ۲۴ ساعته |
| `GET` | `/api/admin/me` | دریافت اطلاعات مدیر لاگین‌شده |
| `GET` | `/api/admin/appointments` | دریافت فهرست و آمار نوبت‌های یک تاریخ مشخص (پارامتر اختیاری `?date=YYYY-MM-DD` بر مبنای تقویم تهران) |
| `PATCH` / `POST` | `/api/admin/appointments/:id/cancel` | لغو نوبت توسط مدیر و آزادسازی بلافاصله بازه زمانی |

## قابلیت‌های تکمیل‌شده در پایان سطح ۱

- **رزرو آسان بدون ثبت‌نام:** ثبت سریع نوبت تنها با نام و شماره تماس مشتری.
- **انتخاب هم‌زمان چند خدمت:** امکان انتخاب چندین خدمت با محاسبه خودکار مجموع زمان و هزینه و منع انتخاب همزمان «اصلاح مو» و «اصلاح مو و ریش».
- **منطقه زمانی دقیق:** کلیه محاسبات زمانی و تاریخ‌ها بر اساس منطقه زمانی رسمی `Asia/Tehran`.
- **رعایت ساعات کاری (R1):** رزرو فقط در بازه ۱۰:۰۰ الی ۲۰:۰۰ و در فواصل ۳۰ دقیقه‌ای با تضمین اتمام تا قبل از ساعت ۲۰:۰۰.
- **تضمین عدم تداخل نوبت‌ها (R2 و FR-9):** جلوگیری از تداخل نوبت‌ها در سطح تراکنش بهینه‌شده Prisma و قید انحصار پایگاه داده PostgreSQL.
- **منع رزرو در گذشته (R3):** عدم امکان انتخاب سانس‌های سپری‌شده نسبت به زمان جاری تهران.
- **کد رهگیری یکتا:** صدور کد رهگیری ۷ رقمی تصادفی و غیرقابل حدس برای هر نوبت.
- **تعطیلی روزهای جمعه:** مسدود بودن رزرو در روزهای جمعه در فرانت‌اند و بک‌اند.
- **پنجره زمانی رزرو:** امکان رزرو تا سقف ۷ روز آینده.
- **پنل مدیریت اختصاصی:** ورود امن، داشبورد روزانه، فیلتر تقویمی هماهنگ با URL، و لغو نوبت بدون حذف فیزیکی رکورد (R4).
- **رابط کاربری مدرن:** کاملاً فارسی، راست‌چین (`RTL`) و واکنش‌گرا با فونت وزیرمتن.

## محدودیت‌ها و قابلیت‌های پیاده‌سازی‌نشده

جهت شفافیت، موارد زیر در سطح ۱ پیاده‌سازی نشده‌اند و به فازهای بعدی موکول گردیده‌اند:

1. **لغو نوبت توسط مشتری (FR-4):** با توجه به نبود حساب کاربری، سازوکار احراز هویت مشتری جهت لغو نوبت (مثلاً ترکیب کد رهگیری + شماره تماس یا پیامک تأیید) در فازهای بعدی توسعه خواهد یافت.
2. **استعلام برخط سانس‌های اشغال‌شده در فرم رزرو:** در نسخه فعلی، سانس‌های رزروشده در تقویم فرانت‌اند پنهان نمی‌شوند؛ بلکه در صورت تلاش برای رزرو وقت تکراری، سیستم با بازگرداندن خطای `409 Conflict` از ثبت آن ممانعت می‌کند. قابلیت پنهان‌سازی سانس‌های رزروشده در فرم مشتری در فاز بعد تکمیل خواهد شد.
3. **درگاه پرداخت آنلاین:** طبق مشخصات اولیه پروژه، هیچ درگاه پرداختی وجود ندارد و تسویه‌حساب صرفاً حضوری است.
4. **تعریف روزهای تعطیل مناسبتی در پنل ادمین:** تقویم تعطیلات فعلی صرفاً شامل جمعه‌ها است و امکان ثبت تعطیلات پویا توسط مدیر پیاده‌سازی نشده است.
5. **محدودیت تعداد نوبت‌های هم‌زمان یک مشتری:** محدودیتی برای سقف تعداد نوبت‌های یک شماره موبایل در سیستم وجود ندارد.
